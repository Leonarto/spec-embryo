# Precompiled local UI runtime — proposed implementation contract

Astra technical decision; independent review required before implementation. This is a material correction to the shipped `spm ui` runtime within SPEC-062, not a benchmark-only preview. The valid final 9a detail failure (Task 398 ms / Spec 523.5 ms p95) remains recorded. Precompilation removes first-request development compilation; it does not promise a warm-tail or acceptance pass.

## 1. Runtime and user contract

- Normal `spm ui [--host H] [--port P]` serves precompiled client and SSR artifacts. Keep the Bun CLI; launch the server with an actual Node executable resolved from PATH. Require Node >=22.12.0 (major >=23 also accepted); report its resolved executable/version. Missing/older Node is an actionable startup error, never a Bun/DEV fallback. Validate with the existing Node25.6.0 acceptance runtime; do not upgrade Kit/Svelte/Vite for this change.
- Use official `@sveltejs/adapter-node` **5.5.8**, pinned exactly in the root/web manifests and lock. Its published source declares Kit ^2.4.0, including installed 2.55.0. Replace adapter-auto; keep the existing Kit2 `svelte.config.js` API. Use `out:'build'`, `precompress:true`, `envPrefix:'SPM_SERVER_'`.
- A small shipped `web/runtime/server.mjs` imports generated `../build/handler.js` and uses Node's built-in HTTP server. No new web framework, alternate data engine, private `.svelte-kit` server import, Vite preview server or production transpiler. The official adapter handler handles assets, SSR, endpoints, streaming and actions.
- `spm ui --dev` is the explicit contributor compiler workflow, retaining existing packaged/source Vite path support. It does not require production artifacts. Reject a value supplied to this boolean flag; advertise DEV mode. Installed source/config remains shipped for compatibility, but ordinary users do not compile or write inside the installation. Keep `bun run ui` as the ordinary precompiled launcher; document `bun run web:build` once for a checkout and `bun run ui -- --dev` for live development.

## 2. Artifact build, identity and release

Add an explicit root `web:build` command, backed by `scripts/build-ui.ts`, that runs Kit sync and Vite build using installed Node/tool entrypoints, then writes the manifest. The low-level web build remains usable, but it does not by itself certify a release manifest. No build during `spm ui`, install, postinstall or first request. Root `prepack` runs this explicit build/verification pipeline; publishing skill runs it before dry-run and checks the resulting archive. No actual publish/version bump is part of this task.

`web/build/spm-manifest.json` schema1 contains package name/version, adapter/Kit/Svelte/Vite versions, Node build version, `sourceDigest`, `lockDigest`, deterministic sorted input hashes and output `{path,bytes,sha256}` entries. Build ID is a SHA256 of canonical identity/content data, excluding clocks/absolute paths. Inputs include root/web package manifests, bun.lock, all product `src/**`, `web/src/**`, `web/runtime/**`, and shipped web build/config helper files; exclude AGENTS, tests, docs/memory, outputs, dependencies and runtime project contents. The wrapper source is included. No timestamp freshness heuristic and no reading the user's project for build validation. Root package files must include bun.lock so the same identity can be checked after extraction.

The builder hashes inputs before and after building and fails if they changed. It invalidates/removes any prior success manifest before starting, cleans the output, and publishes a new manifest only after successful build plus complete output inventory. A failed/interrupted build cannot leave a valid old manifest over partial new output. Runtime source edits or package version/lock changes require an explicit rebuild. Runtime concurrent rebuilds are unsupported; document stopping the server before rebuilding instead of adding a build daemon.

Before spawning Node or binding a listener, the CLI verifies the manifest schema/name/version/tool identity, recomputed source/lock identity and every listed output's bytes/hash, rejecting missing/unlisted output files, symlinks or traversal. Enumerate only the known package-owned input/output roots; no project-data scan. Validation occurs once at startup, never per HTTP request. Record its startup cost rather than moving it into a hidden warmup. Manifest hash consistency is stale/corruption detection, not cryptographic trust in an attacker-owned installation.

Missing, partial, tampered or stale output exits nonzero before serving. Checkout guidance: `bun run web:build` or explicit `--dev`. Installed-package guidance: reinstall a complete matching package. No automatic rebuild/fallback. Source commit is recorded separately for verification; source bytes/build ID are authoritative, so metadata-only commits do not force a rebuild.

Root package `files` adds `web/build`, `web/runtime` and bun.lock; keep `.svelte-kit`, tool caches, verification, managed memory and tests excluded. `.gitignore` adds `/web/build/`. Build artifacts are release assets, never tracked source. The build bundles server-side application/root services into JavaScript; no emitted import may require TS stripping, `.svelte` evaluation, development source paths or generated files outside the shipped output. Move web `@lucide/svelte` to web devDependencies if needed to make the adapter bundle it; do not perform a broad dependency-pruning refactor. Every remaining bare server import must be an explicit installed root production dependency. Archive validation checks the actual dependency closure, not only the presence of handler.js.

## 3. Host, port, project and environment

- Default host127.0.0.1/port4173 stays. Parse the entire port string as an integer in1..65535; reject malformed/missing valued flags. Accept hostnames or IP literals, not URLs/paths/credentials. Format IPv6 origins with brackets.
- The production wrapper owns actual binding: requested port through min(requested+25,65535), advancing only on EADDRINUSE. Do not rely on a check-then-bind result. Other bind failures fail. No unbounded scan or port0. DEV can retain the existing bounded probe with Vite strictPort; a race is an explicit error.
- Preserve the CLI's current project choice (its rootDir/cwd); canonicalize it once and pass absolute `SPM_PROJECT_ROOT` before importing the generated handler. Do not introduce a new ascendant-root rule in this change. Builds never embed this value. Child cwd is the selected project; assets resolve relative to the installed handler, not cwd. Repo/org/session visibility policies remain as today.
- One advertised origin per server: `http://<bind host>:<actual port>`. Wildcard0.0.0.0 advertises127.0.0.1; wildcard:: advertises[::1]. For intentional LAN access, use the actual interface IP/hostname as `--host`. The wrapper accepts only this normalized Host authority (including port, case-normalized hostname); other/malformed/duplicate Host values receive421/400 before any Kit/project load. This deliberately prevents arbitrary Host/DNS-rebinding access. Wildcard binds do not imply accepting every Host alias. No wildcard trusted-origin option is added.
- Clear inherited `SPM_SERVER_*`, socket-activation variables and origin/proxy override inputs in the server environment; then set `NODE_ENV=production`, exact `SPM_PROJECT_ROOT`, `SPM_SERVER_ORIGIN` to the advertised origin and `SPM_SERVER_BODY_SIZE_LIMIT=Infinity`. The last setting preserves the current DEV action's unbounded request-body contract rather than accidentally introducing adapter512K rejection for question/recovery text. No new body-limit feature here. Do not load project `.env` or let unrelated PORT/HOST/ORIGIN/X-Forwarded-* inputs change binding/trust. Do not copy secrets into manifest/logs.
- Keep Kit2 production CSRF origin checks enabled, trustedOrigins empty, and existing CSP behavior. Same-origin native/enhanced canonical questions must work; foreign/missing Origin form requests must be rejected without a write. Do not disable CSRF to fix a packaging action failure. Only static client assets are public; never serve package source, build server files, user's `.specpm`, documents, arbitrary `/@fs` paths or DEV endpoints.

## 4. Startup and lifecycle

Parent validates artifacts and Node, launches one child with IPC in the parent's process group (preserves existing controlled harness/terminal group ownership), and waits. The wrapper binds its selected socket, sets origin, dynamically imports/initializes the generated handler, then sends one structured ready message with actual host/port/origin/build ID/version. Before handler readiness, any early connection gets503; no project prefill, synthetic HTTP warmup or scan of documents at startup. Print the user-facing ready URL only after the message; initial progress text must not claim readiness. Startup failure sends/prints a clear error and closes its listener.

Wrapper and parent handle SIGINT/SIGTERM idempotently. Parent forwards to its own child and does not exit before child close; wrapper stops accepting, closes idle connections and allows in-flight requests up to30s, then closes remaining connections. Parent enforces a35s final child deadline. IPC disconnect triggers the same wrapper shutdown so a dead parent does not leave the UI listener running. Do not kill by port/name or reuse the native-agent general runner. Tests must prove parent/child/listener closure, repeated signals and startup cancellation. Preserve a confirmed write result if its response completes; do not add new transaction/cancellation semantics. Runtime emits errors and nonzero exits honestly.

No first-use compiler, .svelte-kit generation, Vite cache or package-tree write occurs in this path. Installed directory can be read-only. Incoming requests still call the same request-scoped fresh reader, sourceRevision/specRevision, bounded memo, DTO validators and canonical guarded action. No context/result cache, preload endpoint, polling or background project refresh is added.

## 5. Ownership and finite gates

One Sol owns this cohesive runtime/build slice: src/commands/ui.ts, src/services/ui.ts plus a small ui-artifacts helper, CLI help; web/runtime (with local AGENTS), web/svelte.config, root/web package and lock, build script, tests/ui and new artifact/runtime/packaging tests. Root maintains specs/task/state and merges README/architecture/AGENTS/publish-skill updates. Existing editor/controller, repository/memo, domain/graph, UI components and acceptance thresholds are out of scope. H can prepare harness changes in isolation but must consume the reviewed runtime commit before final measurements.

1. Unit/artifact gates: whole flag parsing and port bounds, allowed origins/Host normalization, absent Node, missing/mixed/stale/tampered artifacts, same-version source mutation, changed lock, failed build without success marker; identities ignore clocks/project paths and survive extraction under a prefix with spaces. Normal launch cannot import Vite or invoke a compiler; DEV is explicit.
2. Real lifecycle/package gate: build once, fresh tgz and owned prefix with production dependencies, real installed bin from two external fixture roots, read-only package tree. All six routes, static CSS/fonts/icons, lazy detail/Mermaid/editor, SSR/noJS questions and guarded success400/409/recovery work. Host spoof/foreign Origin form rejected with unchanged bytes; legitimate same-origin POST including >512KiB recovery body preserves current semantics. Missing/stale artifacts fail before listen. Busy-port fallback/IPv6 where available, interrupt/disconnect cleanup. No real repo documents mutated. Recheck initial Tasks static JS closure and generated output imports.
3. Source/runtime freeze and independent code+package review precede the one final acceptance window. Update the finite harness to recognize the new shipped ready signal and to build outside the interval, then give every cold sample a new Node server/browser/profile with no document preload. Warm samples use the same shipped runtime. Account for the explicit build in release preparation, startup/manifest cost in startup evidence, and full navigationStart through hydration+2RAF in route samples. Preserve20cold,5+20warm and detail100rows/trusted-click+2RAF semantics. Budgets remain cold2.5s, Tasks/Specs warm800ms, detail300ms; loading150ms retains its original origin and blank-before-HTML cannot be called an app indicator. No OS-cache purge or promise that precompilation alone passes. Repeat only invalidated final gates and required combined checks; keep old failures historical.

## Independent review closure

The independent Astra review approved implementation of the frozen design (30c7c674a2a764d957eec78f8f68bc244c5b368322529a10901b3189ae45cc91), without acceptance credit. Two implementation clarifications make existing requirements explicit: the generated output inventory excludes only its own spm-manifest.json to avoid a self-referential hash; the Host check inspects rawHeaders for duplicates and strictly normalizes hostname/IPv6/port without accepting a different authority. These do not authorize broader features or relax the gates above.
