# Problem

Spec Embryo now depends more heavily on generated adoption artifacts such as the migration guide and direct agent brief. Those files carry repo-local guidance that agents may read long after the CLI version or deterministic guidance renderer has changed.

Right now we can refresh those artifacts with `spm init`, and `doctor` can explain newer capabilities in its live output, but there is still a trust gap:

- a repo-local migration guide or direct agent brief can drift from the current deterministic renderer
- an adopted repo can keep stale generated guidance on disk without `doctor` flagging it
- a future agent may read the stale file directly and act on older SpM usage policy even though the installed CLI knows better

If generated adoption artifacts are part of the contract, the tool needs to detect when they are missing or stale and tell humans or agents how to refresh them before relying on them.

# Goals

- Make `doctor` compare generated adoption artifacts against the current deterministic renderer and surface drift as an actionable finding.
- Detect both missing and stale repo-local migration guides and direct agent briefs.
- Keep the guidance refresh path deterministic and aligned with `spm init`.
- Help future agents distinguish "live doctor guidance" from "repo-local generated artifacts that may be out of date."

# Non-Goals

- Do not diff arbitrary user-authored docs outside the generated adoption artifact set.
- Do not add checksum files or a separate artifact registry in this slice.
- Do not introduce network-backed release note checking or remote artifact sync.

# Constraints

- Drift detection should use the same deterministic renderers that generate the migration guide and direct agent brief.
- `doctor` should remain read-only; it can suggest `spm init` or other deterministic refresh commands, but it should not rewrite files itself.
- Findings should stay concise in the default report and still expose enough context in JSON and verbose output for another agent to act.

# Proposed Approach

Treat the generated adoption artifacts as deterministic outputs owned by the current CLI:

1. Build the current expected migration guide and direct agent brief during `doctor`.
2. Compare those expected strings with the files currently present in the repo's managed adoption artifact paths.
3. Surface findings when:
   - a generated artifact file is missing
   - a generated artifact file exists but differs from the current renderer
4. Point the user or agent to `spm init` as the normal refresh path, since that command now rewrites stale generated adoption artifacts and config on adopted repos.

# Detailed Specification

## Artifact set

This slice covers the deterministic adoption artifacts already generated by `spm init`:

- `migration-guide.md`
- `direct-agent-brief.md`

The file locations should continue to come from the existing managed memory home and artifact-path helpers.

## Doctor behavior

After `doctor` has enough context to render the current guidance, it should:

- render the expected migration guide for the repo
- render the expected direct agent brief for the repo
- read the existing artifact files if present
- compare file presence and content

Expected outcomes:

- missing file -> warning finding
- stale content -> warning finding
- matching file -> no finding

## Guidance and hints

The finding hint should clearly explain that:

- the repo-local generated guidance no longer matches the current CLI contract
- a future agent could read stale repo-local guidance
- `spm init` is the deterministic refresh path

## Compatibility

Repos that never relied on the adoption artifacts should still remain usable, but `doctor` should teach that generated guidance is now part of the supported contract and should be refreshed when stale.

# Edge Cases

- A repo may intentionally keep the artifacts missing because they were deleted manually; `doctor` should still report that they are missing.
- A repo may have stale artifacts even when `tool_version` matches, for example after manual edits or partial cherry-picks; drift detection should not rely only on version mismatch.
- A repo may be partially adopted; the findings should remain actionable without assuming the repo is already fully healthy.

# Acceptance Criteria

- `doctor` warns when the generated migration guide is missing or stale.
- `doctor` warns when the generated direct agent brief is missing or stale.
- The finding hint points to `spm init` as the refresh path.
- Regression tests cover missing and stale artifact scenarios.

# Open Questions

- Should a later slice surface a lightweight digest or last-generated timestamp for adoption artifacts, or is direct drift detection enough?
